# Markdown

## 结构

- 标题树按 MECE 组织：兄弟节互斥、并集穷尽；「其他」类内容超过两成说明分类失败，重新划分
- 仅一个 H1（文件标题）；标题逐级递进，不跳级（H2 → H4 是错误）
- 重要信息前置，不写导览语（「下面我们将介绍…」）
- 密集信息用列表不用长段落；MUST NOT 使用表格，一律用列表替代
- 一篇一主题，命中两个主题就拆分

## 格式

- 代码块必须带语言标签；前后对比用 `diff` fence
- `**bold**` 不用 `__bold__`；`*italic*` 不用 `_italic_`；命令、路径、标识、值用行内 code
- `---` 只用于重大分节，不夹在标题之间当装饰
- GFM alerts 每篇 0–2 个，只给关键边界提醒，不当装饰；面向 AI 阅读的规则文档不用 alerts

  ```markdown
  > [!WARNING]
  > 该操作不可逆，执行前先备份。
  ```

- 会打断阅读流的长参考内容收进 `<details>`

  ```markdown
  <details>
  <summary>完整示例</summary>

  正文（summary 后必须空一行）。

  </details>
  ```

## 图示

- 表达架构、流程、关系优先 Mermaid

  ```mermaid
  graph TD
      A[Input] --> B{Decision}
      B -->|Yes| C[Action]
      B -->|No| D[Skip]
  ```

- 结构化 ASCII（目录树、状态机、拓扑）信息密度高，可用；MUST NOT 使用装饰性 ASCII（花框、分隔线、ASCII art）

## AI 痕迹

写完自查，命中即改写。

- 总结式过渡：段落开头回顾上一段（「至此配置完成…」「现在我们已经了解了…」），删掉，直接进入下一个论点
- 断续短句：一个完整意思被劈成几个碎片，合成一句；为强调而用的短句不在此列

  ```diff
  - 以前需要手动。现在自动了。这节省了时间。
  + 这一步以前要手动做，现在自动完成。
  ```

- 规格书腔：像在念数据手册（「提供了…」「是可配置的」「被显式标注为…」），改写成人读的动作
- 冷开场：段落首句能单独当标题用，说明它没有承接上文；用「因为」「一旦」这类词把上一段的主语接过来
- 拟人化：机器不做人的动作（「把 URL 交给浏览器」→「浏览器请求该 URL」；「token 持有…」→「token 存储在…」）
- 复用框架：论述角度来自模板而非本文（「多数团队面临的问题是…」）

## 术语

- 概念先行（ISO 704）：先明确概念，再找行业标准词直接采用；不确定时停下查证
- 一概一词：同一概念在一篇文档内不换词（不「聚合/聚合体/聚合对象」混用）
- 中英锚定只在首次出现：`aggregate（聚合）`，此后统一用一种形式
- 工程语境惯用的英文术语保留原词（`idempotent`、`debounce`），不强译、不造半英半中词
- 约束用「约定」，描述现状用「结构」——目录树写「目录约定」才构成约束
- 设计讨论中的内部隐喻与自造词汇体系落文档时翻译回平实事实，不让读者反查会话语境才能理解

## 来源

- 机制/事实类结论必须标注可回溯的来源（文档链接、代码位置、标准编号）——查证结论与臆测混写会让读者无法分辨可信度；写不出来源的降级为推测措辞
